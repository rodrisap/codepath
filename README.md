# CodePath

A personal learn-to-code site: **Python → SQL → Java**. Everything runs in your browser. There's no account and no server, and your progress stays on your machine.

Every lesson follows the same rhythm:

**Goal → Concept → Worked example with a step-by-step trace → Try it → Exercises (with tests, 3 hints and a solution) → Common mistakes → Quick check**

The trace tables are **generated by actually running the code**, so every "how was this value produced" step is correct by construction.

## Run it locally

You need [Node.js](https://nodejs.org) 22 or newer.

```bash
npm install
npm run dev
```

Then open the address it prints (usually http://localhost:5173). The first time you open a lesson, Python takes a few seconds to load. After that the browser caches it.

## Useful commands

| Command | What it does |
|---|---|
| `npm run dev` | Start the site locally with live reload |
| `npm run build` | Type-check and build the static site into `dist/` |
| `npm run preview` | Serve the built site locally |
| `npm test` | Unit tests (progress, spaced repetition, tracer, checks) |
| `npm run content` | Verify every lesson and regenerate the step-by-step traces |
| `npm run verify` | Same checks, without writing files (used by CI) |
| `npm run e2e` | Browser smoke test (needs `npm run dev` running and Chromium) |

`npm run content` checks that every solution **passes** its tests, that every listed wrong answer **fails**, and that "predict the output" answers match the real output. See [docs/CONTENT_FORMAT.md](docs/CONTENT_FORMAT.md) to add lessons.

## Deploy

### GitHub Pages

1. Push this repository to GitHub.
2. In the repository, go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**.
3. Every push to `main` runs `.github/workflows/deploy.yml`: tests → lesson verification → build → publish.

Your site appears at `https://<your-username>.github.io/codepath/`.

GitHub Pages can't send the special headers that Python's `input()` needs (cross-origin isolation). A tiny service worker (`coi-serviceworker`) adds them. On the very first visit the page reloads once by itself.

### Vercel

Import the repository in Vercel. `vercel.json` already sets the build command, the output folder and the headers.

## Your progress

Progress, code drafts, notes and settings are saved automatically in the browser (IndexedDB, with a localStorage backup). **Settings → Export progress** downloads a JSON file, and **Import** restores it on any computer. Export now and then: clearing browser data deletes local progress.

## How it works

| Part | Technology |
|---|---|
| App | Vite + React + TypeScript, Tailwind CSS |
| Editor | CodeMirror 6 |
| Python | [Pyodide](https://pyodide.org) (CPython compiled to WebAssembly) in a Web Worker |
| SQL (phase 3) | sql.js (SQLite compiled to WebAssembly) |
| Storage | IndexedDB via `idb-keyval` |

Main folders:

```
content/            lessons as data (Markdown + TypeScript), one folder per lesson
src/runners/        the CodeRunner interface + Python worker + harness.py (runs, tests, traces)
src/features/       pages: lesson, workbench (editor/output), trace, review, playground, …
src/progress/       saving progress, spaced repetition, streaks, export/import
src/errors/         the error translator (raw error → plain English)
scripts/content.ts  the lesson checker/generator
```

`src/runners/python/harness.py` is shared by the browser and the lesson checker, so what you see in the app is exactly what was verified.
